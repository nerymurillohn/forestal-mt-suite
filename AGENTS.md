## Project Overview

The **Forestal MT Suite** is a pure **source-of-truth data repository** for Forestal MT (Forestal Murillo Tejada S. de R.L. de C.V.), a Honduran producer of traditional botanical products. This repository contains structured product data, brand guidelines, company information, and assets that feed downstream projects for e-commerce, documentation, and regulatory compliance.

**Repository Type:** Data repository (NOT an implementation repository)
**Primary Purpose:** Single source of truth for all Forestal MT brand and product data
**Products:** 46 SKUs across 3 collections (Batana Oil, Stingless Bee Honey, Traditional Herbs)
**Export Readiness Score:** 95/100 (audited 2025-11-11)

## CRITICAL Architecture Principle

### ⚠️ THIS IS A PURE DATA REPOSITORY

**DO NOT create implementation code in this repository.**

```
✓ CORRECT: Store data, documentation, blueprints, assets
✗ WRONG: Store generator/, templates/, styles/, outputs/, src/, lib/
```

**projects/ Folder Rule:**
- Contains ONLY blueprints and documentation
- NO implementation folders (generator/, templates/, styles/, outputs/)
- Actual implementations are separate projects that consume data from this repo

**Example Correct Architecture:**
```
forestal-mt-suite/                    ← Data repository (this repo)
├── products-data/                    ✓ Product data (JSON, Excel)
├── docs/                            ✓ Brand guidelines, company info
├── assets/                          ✓ Fonts, logos, templates
└── projects/sds-tds-generator/      ✓ Blueprint ONLY
    ├── README.md                    ✓ Project overview
    ├── blueprint.md                 ✓ Implementation plan
    └── source-files-manifest.md     ✓ Input file inventory

forestal-sds-tds-generator/          ← Implementation project (separate repo)
├── config.yaml                      ✓ Points to ../forestal-mt-suite
├── generator/                       ✓ Implementation code
├── templates/                       ✓ Document templates
├── styles/                          ✓ Styling logic
└── outputs/                         ✓ Generated files
```

**If you create implementation folders in this repo, you will break the architecture.**

## Automation Scripts

### ⚠️ MUST RUN AFTER FILE CHANGES

These scripts maintain autogenerated documentation and must be run after modifying repository contents:

#### 1. Generate Inventory (After ANY file changes)
```bash
python tools/generate_inventory.py
```
**When to run:**
- After adding/removing/modifying files
- After restoring files from git history
- After merging branches

**What it does:**
- Updates `INVENTORY.md` with complete file listing
- Updates `README.md` with repository statistics
- Updates `REPOSITORY_INFO.md` with metadata
- Generates SHA-256 checksums for all files

**Expected changes:**
- `INVENTORY.md` - File count, sizes, timestamps, checksums
- `README.md` - Total files, directories, size
- `REPOSITORY_INFO.md` - Last update timestamp

#### 2. Build Product Data (After Excel changes)
```bash
python tools/build_product_data.py
```
**When to run:**
- After modifying `products-data/*.xlsx` master files
- When adding new SKUs
- When updating product specifications

**What it does:**
- Parses Excel master files
- Generates `products-data/sku-base.json`
- Generates `products-data/catalogue.json`
- Validates data integrity

#### 3. Verify Product Assets
```bash
python tools/verify_product_assets.py
```
**When to run:**
- Before committing product changes
- After adding hero images
- As pre-push quality check

**What it does:**
- Validates SKU → hero image references
- Checks for orphaned hero images
- Verifies naming conventions
- Reports missing assets

## File Conventions

### SKU Naming Convention
```
FMT-{COLLECTION}-{PRODUCT}-2025
```

**Components:**
- `FMT` - Forestal MT brand prefix
- `{COLLECTION}` - 2-4 letter code (BO=Batana Oil, SBH=Stingless Bee Honey, TH=Traditional Herbs)
- `{PRODUCT}` - 2-4 letter product code (RBO=Raw Batana Oil, RWH=Raw White Honey)
- `2025` - Year suffix

**Examples:**
- `FMT-BO-RBO-2025` - Raw Batana Oil
- `FMT-SBH-RWH-2025` - Raw White Honey
- `FMT-TH-WYB-2025` - Wild Yemeri Bark

**Validation regex:**
```regex
^FMT-[A-Z]{2,4}-[A-Z]{2,4}-2025$
```

### Hero Image Naming Convention
```
{sku-lowercase}-hero.png
```

**Rules:**
- SKU converted to lowercase
- Suffix: `-hero.png`
- Location: `assets/hero-images/`
- Format: PNG only

**Examples:**
- `fmt-bo-rbo-2025-hero.png`
- `fmt-sbh-rwh-2025-hero.png`
- `fmt-th-wyb-2025-hero.png`

**Validation regex:**
```regex
^fmt-[a-z]{2,4}-[a-z]{2,4}-2025-hero\.png$
```

## Data Versioning

### Semantic Versioning

Product data follows **Semantic Versioning (MAJOR.MINOR.PATCH)**:

**Current Version:** Check `products-data/data-manifest.json` → `version` field

**Version Numbering:**
- **MAJOR (1.0.0 → 2.0.0)**: Breaking changes
  - SKU format changes
  - Schema breaking changes
  - Removal of products/collections
- **MINOR (1.0.0 → 1.1.0)**: Backward-compatible additions
  - New products added
  - New collections added
  - New optional fields
- **PATCH (1.0.0 → 1.0.1)**: Backward-compatible fixes
  - Price updates
  - Typo corrections
  - Metadata updates

### Version Update Process

When making data changes:

1. **Determine version bump type** (MAJOR, MINOR, or PATCH)
2. **Update `products-data/data-manifest.json`**:
   ```json
   {
     "version": "1.1.0",
     ...
   }
   ```
3. **Add entry to `CHANGELOG.md`** documenting changes
4. **Run full test suite**: `pytest tests/ -v`
5. **Regenerate inventory**: `python tools/generate_inventory.py`
6. **Commit with version tag**:
   ```bash
   git add products-data/ CHANGELOG.md
   git commit -m "release: product data v1.1.0"
   git tag -a v1.1.0 -m "Product data version 1.1.0"
   git push origin main --tags
   ```

### CHANGELOG.md

All data changes **must** be documented in `CHANGELOG.md` using [Keep a Changelog](https://keepachangelog.com/) format:

```markdown
## [1.1.0] - 2025-11-15

### Added
- 5 new products in Traditional Herbs collection

### Changed
- Updated retail pricing for Batana Oil products

### Fixed
- Corrected HS code for FMT-TH-WYB-2025
```

**Categories:**
- **Added**: New products, collections, or fields
- **Changed**: Modifications to existing data
- **Deprecated**: Features being phased out
- **Removed**: Products or fields removed
- **Fixed**: Bug fixes or corrections
- **Security**: Security-related changes

### Version History

View all versions:
```bash
# Git tags
git tag -l "v*"

# Changelog
cat CHANGELOG.md
```

**Rollback to previous version:**
```bash
git checkout v1.0.0 -- products-data/
```

## Data Validation Rules

### JSON Schema Validation

Product data is validated against a formal JSON Schema located at:
```
tests/schemas/product-schema.json
```

**Run schema validation:**
```bash
pytest tests/test_semantic_validation.py::test_sku_base_schema_validation -v
```

### Required Fields (SKU)
Every SKU in `products-data/sku-base.json` must have:

```json
{
  "sku": "FMT-XX-XXX-2025",          // Required, must match naming convention
  "product_name": "Product Name",     // Required, non-empty, 3-200 chars
  "collection": "Collection Name",    // Required, one of: Batana Oil, Stingless Bee Honey, Traditional Herbs
  "botanical_source": "Latin name",   // Required, Genus species or Genus spp. format
  "ingredients": "Composition",       // Required, minimum 10 characters
  "country_of_origin": "Honduras",    // Required, must be "Honduras"
  "hs_code": "1234567890",           // Required, 6-10 digits (integer or string)
  "hero_image_reference": "path",     // Required, must match SKU naming convention
  "doc_reference": "path"             // Required, must point to collection documentation
}
```

### Format Validation Rules

**HS Codes:**
- Must be 6-10 digits
- Can be integer or string
- Valid examples: `15159099`, `33059000`, `34011100`

**Botanical Names:**
- Format: `Genus species` (e.g., `Elaeis oleifera`)
- Format: `Genus spp.` (multiple species, e.g., `Amaranthus spp.`)
- Special case: `Multiple sources` (for herb blends)
- First letter capitalized, species lowercase
- Must be valid Latin binomial nomenclature

**SKU Naming:**
- Pattern: `FMT-{COLLECTION}-{PRODUCT}-2025`
- Collection codes: `BO` (Batana Oil), `SBH` (Stingless Bee Honey), `TH` (Traditional Herbs)
- All uppercase
- Regex: `^FMT-[A-Z]{2,4}-[A-Z]{2,4}-2025$`

**Country of Origin:**
- Must be exactly `Honduras` for all products
- No variations or abbreviations allowed

### Optional Fields (Graceful Degradation)
```json
{
  "seal": "Pure & Unrefined",              // Default: "Traditional Quality"
  "processing_method": "Description",      // Default: "Traditional methods"
  "traditional_uses": ["Use 1", "Use 2"], // Can be empty array or string
  "part_used": "kernel"                    // Default: "whole plant"
}
```

### Cross-Reference Integrity

**SKU → Hero Image:**
- Every SKU must have corresponding hero image
- Format: `assets/hero-images/{sku-lowercase}-hero.png`

**SKU → Documentation:**
- Product collections must have docs in `docs/collections/`
- Product specifications must align with Excel masters

**Validation:**
```bash
# Automated validation
pytest tests/test_data_integrity.py

# Manual verification
python tools/verify_product_assets.py
```

## Common Pitfalls & Solutions

### 1. "Why can't I push to main?" (HTTP 403)
**Problem:** Main branch has push restrictions.

**Solution:** Always use feature branches:
```bash
git checkout -b claude/my-feature-sessionid
git push -u origin claude/my-feature-sessionid
```

### 2. "CI failed: pytest found no tests"
**Problem:** Test suite not properly installed or tests missing.

**Solution:**
```bash
# Verify test files exist
ls tests/test_*.py

# Run locally first
pytest tests/ -v

# Commit test files
git add tests/
```

### 3. "Autogenerated files keep changing"
**Problem:** This is expected behavior.

**Solution:**
- Always run `python tools/generate_inventory.py` after file changes
- Commit autogenerated files along with your changes
- CI allows timestamp-only changes in these files

### 4. "I accidentally created implementation folders in projects/"
**Problem:** Violates pure data repository architecture.

**Solution:**
```bash
# Remove implementation folders
rm -rf projects/my-project/generator/
rm -rf projects/my-project/templates/
rm -rf projects/my-project/styles/
rm -rf projects/my-project/outputs/

# Keep only blueprints
git add projects/my-project/
git commit -m "refactor: remove implementation folders from data repo"

# Create separate implementation project
mkdir ../my-implementation-project
cd ../my-implementation-project
# Create config.yaml pointing to ../forestal-mt-suite
```

### 5. "Hero image not found errors"
**Problem:** Image naming doesn't match convention or file missing.

**Solution:**
```bash
# Check naming convention
ls assets/hero-images/ | grep fmt-

# Verify pattern: {sku-lowercase}-hero.png
# Correct: fmt-bo-rbo-2025-hero.png
# Wrong: FMT-BO-RBO-2025-hero.png (uppercase)
# Wrong: fmt-bo-rbo-2025.png (missing -hero suffix)

# Run validation
python tools/verify_product_assets.py
```

### 6. "Modified master template by accident"
**Problem:** Edited letterhead template directly instead of cloning.

**Solution:**
```bash
# Restore from git
git checkout HEAD -- assets/templates/official-letterhead/

# In implementation project, always clone first
cp ../../forestal-mt-suite/assets/templates/official-letterhead/docx/forestal-mt-letterhead.docx ./temp.docx
# Now modify temp.docx
```
